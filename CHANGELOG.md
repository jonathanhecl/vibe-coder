## [Unreleased]

### Breaking

- **Model/endpoint commands replaced by a provider registry with roles.** `/model`, the role-less `/models`, `/sidecar <model|number>` and the `/decision` model/endpoint subcommands are gone. The new surface is `/providers` (providers plus the model bound to every role), `/provider <NAME> [add|endpoint|key|kind|test|remove]`, `/models [PROVIDER]` (numbered list with colored capability tags) and `/setmodel [PROVIDER] <role> <number|name|off>`, preserving the short `/setmodel main 5` form. Five roles are supported — `main`, `sidecar`, `decision`, `embedding`, `vision` — and only `main` with the completion capability is required to operate; the rest are unset until you bind them. Capability validation uses the model's Ollama tag, or trusts the user (marked *unverified*) for other providers. `/sidecar on|off|status|perm-on|perm-off` and `/decision status|test|assisted on|off` survive as behavior-only toggles, because the per-session sidecar skip and the assisted flag cannot be expressed as a model binding. Settings now persist as `PROVIDER_<NAME>_KIND|ENDPOINT|API_KEY` and `ROLE_<ROLE>_PROVIDER|MODEL`; legacy keys (`MODEL`, `SIDECAR_MODEL`, `MODEL_ENDPOINT`, `MODEL_PROVIDER`, `SIDECAR_ENDPOINT`, `SIDECAR_PROVIDER`, `DECISION_MODEL`, `DECISION_ENDPOINT`, `OLLAMA_HOST`) are migrated on load and replaced on save, so an older binary will no longer find them. First-run onboarding now configures only the Ollama endpoint and one `main` model (the RAM-based recommendation), instead of asking for a sidecar and a decision model.
- **JEV Style replaced by a generic Decision Model (System One protocol).** The old `internal/jevstyle` (v1/v2 letter-answer mode via `/api/chat`) and `internal/jevstylev3` packages are gone; a single `internal/decision` client now speaks `POST <endpoint>/v1/systemone` with typed `noul`/`choice`/`score` questions against either native Ollama (>= 0.35, models advertising the `decision` capability — verified at startup via `/api/show`) or a custom System One server (`/healthz` + `/v1/systemone`, e.g. `jev-style serve`). Configuration was renamed and old keys are **removed, not aliased**: `JEVSTYLE_V3_ENDPOINT` → `DECISION_ENDPOINT`, `JEVSTYLE_MODEL` is gone — configure an Ollama `decision`-capable model via `DECISION_MODEL` instead (e.g. `nimble`, `tev1`, `clef-flash`). New env vars `VIBE_CODER_DECISION_MODEL` / `VIBE_CODER_DECISION_ENDPOINT` / `VIBE_CODER_DECISION_API_KEY` and flags `--decision-model` / `--decision-endpoint` (the `--jevstyle*` flags no longer exist). Any leftover `JEVSTYLE_*` key in `vibe-coder.env` or the environment prints a one-time startup warning and is ignored. The `/jevstyle` slash command is replaced by `/decision` (status, `<name|number>`, `endpoint <url|ollama>`, `test`, `assisted on|off`, `off`); the `JevDecide` tool is renamed `Decide`; `VIBE_THINKING_NO_JEV_TIMEOUT` is now `VIBE_THINKING_NO_DECISION_TIMEOUT`.
- **RAG embedding model comes from the `embedding` role.** The `--rag-model` flag and its config field are removed; bind the encoder with `/setmodel embedding <number|name>` instead.

### Added

- Permission prompts now expire. The card shows a live `⏳ auto-deny in 3:00` countdown on its input line, and when it reaches zero the action is denied exactly like `Deny once`: nothing runs, no session rule is remembered (so the same action can still be approved later), and the model receives a denial reason naming the timeout together with the instruction not to repeat the request. A run therefore keeps moving while the user is away instead of waiting on a prompt nobody will answer. The wait is repainted in place once per second from a polled stdin read, so it never steals the keypress the ESC monitor would otherwise swallow, and the answer path (a digit without Enter) is unchanged. Configurable with `PERMISSION_TIMEOUT`, `VIBE_CODER_PERMISSION_TIMEOUT` and `--permission-timeout` (Go duration, default `3m`; `off`, `never`, `0` or a negative value waits forever), following the defaults < file < env < CLI precedence. The clock only appears when both stdin and stdout are terminals: piped runs and Windows consoles keep the previous blocking prompt. `/settimeout` shows or sets the bound for the session (`3m`, `90s`, `45` where a bare number means seconds, or `off` to wait until answered), `/save` writes it as `PERMISSION_TIMEOUT`, and `/status` reports the value in force, marking the built-in default.

- MCP server status and best-effort startup. Servers now start independently on their own timeout instead of one serial pass sharing a single budget that aborted the whole load on the first failure — so a broken entry no longer drops every server behind it, and which ones survived no longer depended on Go's map order. `vibe` prints an `mcp` block after the startup banner (and `-p` runs print it too) naming each server with the scope its config came from (`project` overrides `global`), its state and tool count, or the reason it failed; `/mcp` prints the same block inside the session and `/mcp tools` lists the wrapped tool names, while a session with nothing configured gets the `vibe mcp add` hint. Model-facing MCP calls are also bounded by a per-call timeout, their output respects the shared tool output cap (`tools.TruncateOutput`, with an explicit truncation footer), and wrapped names are sanitized and deduplicated across servers.

- Language server diagnostics after every edit. A successful `Edit`/`Write` triggers a request to the file's language server over stdio (a minimal LSP 3.17 subset: `initialize`/`initialized`, `didOpen`/`didChange` with full-text sync, pushed `publishDiagnostics`), and the report is recorded as a `[DIAGNOSTICS]` observation beside `[AUTO-TEST]`. Because a server answers in milliseconds what the suite takes a minute to say, a report carrying at least one fresh error skips the auto-test for that edit — and a wait that timed out is never rendered as a clean file, since swallowing it is how a broken server would silently approve edits. The read-only `Diagnostics` tool exposes the same report on demand (`file_path`, optional `severity` filter) without a permission prompt. Servers are resolved per language from the workspace markers (`go.mod` → gopls, `package.json` → typescript-language-server, `Cargo.toml` → rust-analyzer, `pyproject.toml`/`pytest.ini` → `ruff server`/`pylsp`) plus `PATH`, one process per language per session, reused across edits and shut down with the session, so a missing binary, a failed handshake or a crashing server degrades to "no diagnostics" silently and is only visible in the debug log. Configurable with `LSP_ENABLED` (default `auto`), `LSP_SERVERS`, `LSP_AFTER_EDIT` (default `true`) and `LSP_TIMEOUT_MS` (default `5000`, clamped `250..60000`), their `VIBE_CODER_LSP_*` env variants and the `--lsp`/`--no-lsp`/`--lsp-servers`/`--lsp-timeout`/`--no-lsp-after-edit` flags; `/status` reports which servers resolved.

- Named provider registry with reusable providers and five configurable roles. Providers are named entities (`ollama` by default) carrying a kind (`ollama` native, or `openai` for `/v1`-compatible endpoints, inferred from the URL when not forced) plus an endpoint and an optional API key, stored as `PROVIDER_<NAME>_*`. Roles (`main`, `sidecar`, `decision`, `embedding`, `vision`) bind a `(provider, model)` pair via `ROLE_<ROLE>_*`, so any role can run on any provider and the Ollama client now sends `Authorization: Bearer` when an API key is configured. Managed from inside the session with `/providers`, `/provider` and `/setmodel`, and models are listed per provider by `/models [PROVIDER]` with colored capability tags (`completion`, `tools`, `vision`, `thinking`, `embedding`, `decision`). When `main` and `sidecar` share a provider a single client is reused instead of one per role.
- Vision role and automatic image routing. Images are described by the model explicitly bound to the `vision` role (`/setmodel vision <number|name>`) when there is one; otherwise the `main` model takes them when it can see, and failing that the `sidecar`. When no bound or derived model can see, the request gets an honest note instead of a guess. The system prompt, `DescribeImage` tool routing and `/status` all reflect which model is the eyes.
- The `embedding` role is now consumed by RAG. A batched Ollama embeddings client (`POST /api/embed`) computes chunk and query vectors, so retrieval is hybrid: lexical token overlap fused with embedding cosine similarity through reciprocal rank fusion. Bind an encoder with `/setmodel embedding <number|name>` (any model advertising the `embedding` capability); with no bound role — or a provider that cannot embed, such as an OpenAI-compatible one — retrieval stays lexical-only and never fails. Indexing became incremental (each file's content hash is stored, so a re-run only re-embeds changed files and prunes vanished ones) and source files are now split at declaration boundaries (`func`, `type`, `class`, …) instead of fixed windows, with chunks embedded in batches. The `--rag-model` flag is gone: the embedding model comes from the `embedding` role.
- Per-role `keep_alive` policy. Each request now sends the keep_alive of the role it belongs to instead of a single global value: the `main` model stays pinned (`-1`) while worker roles (`sidecar`, `decision`, `embedding`, `vision`) unload after 5 minutes of idle time by default, so a working set larger than memory no longer thrashes on every turn. Configurable with `KEEP_ALIVE_MAIN`/`KEEP_ALIVE_WORKER` (env `VIBE_CODER_*`, flags `--keep-alive-main`/`--keep-alive-worker`); `-1` pins forever, `0` uses the provider default, `N` unloads after `N` idle seconds.

- Harness metrics: every model request records a JSONL entry (provider-reported prompt/completion tokens, prompt-eval/eval/wall timings, tool-call count, tool mode, and estimated system/tool-schema/transcript sizes) to `<state-dir>/metrics/<session-id>.jsonl` (isolated and temporal sessions, and `METRICS_DISABLED`, keep it memory-only). The new `/stats` slash command prints the session summary (requests, tokens, averages, compactions, errors) plus the file path. `/stats` is no longer an alias for `/status`.
- Harness tunables on `config.Config.Harness`, loaded with defaults < file < env precedence: `KEEP_TOOL_RESULTS` (default 6), `TOOL_OUTPUT_MAX_TOKENS` (default 0 = auto), `COMPACT_AT_PERCENT` (default 85, clamped 50–95), and `METRICS_DISABLED` (env `VIBE_CODER_*` variants for all four). Only `METRICS_DISABLED` is consumed so far; the rest feed the upcoming context-budget phase.
- OpenAI-compatible streaming now sends `stream_options.include_usage` and parses the trailing usage chunk (a 400 mentioning `stream_options` retries once without it and remembers per model), and Ollama done-chunk `prompt_eval_count`/`eval_count`/durations are captured as `ollama.Usage`.
- Context memory management: per-request token budget (`CONTEXT_WINDOW` minus output reserve, system prompt, tool schema, and a 5% margin), wire-time masking of tool outputs older than the last `KEEP_TOOL_RESULTS` tool turns (stored transcript never mutated; outputs over 400 chars become `[elided]` stubs with a first-line hint), and a sticky transcript window that only moves when the suffix outgrows the budget. Metrics entries now carry `window_start`, `messages_dropped`, and `compacted`; `vibe-metrics` (`cmd/vibe-metrics`) summarizes JSONL metrics files or directories with totals, averages, masked counts, compactions, and wall-time p50/p95.
- Configurable tool output caps: `TOOL_OUTPUT_MAX_TOKENS` (auto = 15% of the context window, 2000-token floor) now bounds `Read`, `Bash`, `InteractiveBash`, `SendInput`, `HTTPRequest`, `WebFetch`, and sub-agent tools. `Read` truncation notes include the exact line to resume from (`[read truncated at line N; call Read again with start_line=N to continue]`).
- The assistant turn footer now appends the model's generation speed (`42.5 tok/s`, in cyan next to the dim `responded in Xs`) whenever the provider reports eval timings, computed as completion tokens over `eval_duration` rather than the turn's wall clock. Providers that report token counts without durations (OpenAI-compatible endpoints) keep the previous footer instead of showing a wall-clock speed with a different meaning.
- `/skills set` configures `SKILLS_DIRS` interactively: it detects skill folders installed by other tools (`~/.agents/skills`, `~/.claude/skills`, `~/.config/opencode/skills`, `~/.config/devin/skills`, `~/.codex/skills`), offers them as numbered choices alongside custom paths (`/skills set 1,2`, `all`, `none`, `~/my-skills`), updates read-only access immediately and persists via `/save`.
- Agent Skills support: discovers the standard `<root>/<skill-name>/SKILL.md` format (YAML frontmatter `name`/`description`, bundled files like `references/` and `scripts/`) alongside legacy flat `.md` files, under `<cwd>/.vibe-coder/skills`, `<cwd>/skills`, `<configDir>/skills`, and extra roots configured via `SKILLS_DIRS` (file), `VIBE_CODER_SKILLS_DIRS` (env) or `--skills-dirs` (flag) — earlier roots win name collisions. The system prompt now carries only a catalog (name + description); the new `Skill` tool loads the full instructions and bundled-file list on demand, and files under discovered skill roots are read-only accessible without a permission prompt. In-session `/skills` lists name, source and description; `vibe skill list` shows the same.
- `Screenshot` tool: captures a monitor (`all`, `current`, or a 1-based number) or the active window and has a vision-capable model answer a question about it, so the agent can verify visual results of its own work. The capture is analyzed entirely in memory — never saved to disk, the session, or the transcript (file-only backends go through a private tmpfs temp file that is deleted immediately). Backends: `grim` (Sway/Hyprland), `spectacle` (KDE), `gnome-screenshot` (GNOME), ImageMagick `import` (X11), Win32 GDI on Windows, `screencapture` on macOS.

### Changed

- The startup banner now reports the configured thinking level, and `/status` and `/think` share its wording through a single renderer (`tui.ThinkingRow`), so the three surfaces can no longer disagree. The value is the effective level — `default` when nothing is configured, `off` for the legacy no-think flag — followed by the reason it may not be honored: `supported`, `not supported by the model`, or `not applied: main provider is openai`, which is what an OpenAI-compatible endpoint means because the request carries no `think` field and vibe sends no reasoning effort there. A level that cannot be delivered is never reported as supported. `SetRoleModel` also stopped panicking on a freshly built `Config` whose role map was still nil.
- A successful `Bash` card now shows the last four lines of the command's output, dim and indented, under its `done → N lines, XB` summary. The verdict of a build or a test run lives at the end of the output, and collapsing it to a count hid exactly the part worth reading; the count stays so it is still obvious when lines were dropped. Single-line output is not repeated (the summary already shows it), a progress line keeps only its final state (`10%\r50%\r100%` renders `100%`), each line is truncated rune-safely so a long line cannot break the layout, and the tail is terminal-only: redirected output keeps the compact card so `-p`/pipes stay parseable. Errors keep printing the full output as before.
- Enhanced interactive questions from `AskUserQuestion`: prompts now render in modern styled terminal cards with colored markers (`?`, `▸`, `✓`), styled option numbers, clear default hints, flexible input matching (by number, option ID, or label prefix), immediate visual feedback showing the chosen option and label, and human-readable option labels in the tool result summary line instead of raw JSON IDs. In addition, the parser now tolerantly accepts both single-question top-level payloads (`{"prompt":"...","options":["A","B"]}`) and multi-question arrays (`{"questions":[{"id":"q1","prompt":"...","options":["A","B"]}]}`), and tool guidelines have been clarified with explicit examples.
- Shell commands are now classified into a deterministic gravity scale — `READ`, `WRITE`, `DESTRUCTIVE`, `CATASTROPHIC` — instead of only `ls`/`dir`/`pwd` being auto-approved. `READ` is a real reader set (`cat`, `head`, `tail`, `wc`, `grep`, `rg`, `find`, `sed` without `-i`, `sort` without `-o`, `jq`, `stat`, `ps`, `du`, `df`, `git status|diff|log|show|branch|rev-parse|ls-files`, `go version`, `--version`/`--help`, and pipelines composed of them), so inspection stops prompting; `2>/dev/null` no longer disqualifies a read. `DESTRUCTIVE` is now distinct from `WRITE` and covers overwriting data that already exists — `cat a > b` and `cp a b`/`mv a b` onto an existing file, `>` truncation as opposed to `>>` append — while `CATASTROPHIC` is always confirmed. The permission card prints `GRAVITY <level>` plus a one-line reason, and the level is passed to the decision model as runtime context. A verdict that itself reports `high` risk is no longer auto-approved however confident it claims to be, and a read-only command no longer consults the decision model at all.
- Thinking output now renders in gray (`\x1b[90m`) in TUI streaming output, clearly distinguishing the model's reasoning blocks from visible assistant text while preserving readability across dark backgrounds.
- Skills are no longer inlined into the system prompt: only the catalog (name + description) is included, and the full content loads through the `Skill` tool when the agent needs it — large skill collections no longer inflate every request.
- `DescribeImage` now answers focused questions. A specific `question` ("Is the Save button visible?") switches the vision model to an answer-only mode instead of describing the whole image; omitting it keeps the thorough general description. The same applies to `Screenshot`, which shares the refactored vision routing.

- `/save` now says where it saved. An isolated run reports `Saved isolated session (<id>) and settings - still isolated in <cwd>` (or `Saved settings - isolated session has no messages yet, still isolated in <cwd>` when the transcript is empty), so the confirmation can no longer read as a user-level save.

- `/stats` now renders through the same block layout as `/status` — the `vibe stats` heading, an aligned label column, the request count in white with any error count in red, and the per-request averages dimmed — instead of dumping plain `Label: value` lines. `metrics.Summary.Format()` was removed, since `/stats` renders the summary from its fields like every other command.
- The startup banner and `/providers` now report role wiring instead of a fixed Model/Sidecar pair. The intro lists `Session` and then a `Models` section with one bullet per role in the `Label [provider] model` shape (Main, Sidecar, Rabbit/Fast, Decision, Vision, Embedding), and the mode flags (the endpoint stays in `/providers`, which owns endpoint configuration); a role bound to a model that can see images carries the cyan `vision` tag; a role with no binding shows which role it falls back to (`Fallback to Sidecar  (set it with /setmodel <role> MODEL)`, naming the role instead of repeating its model) or the behavior it degrades to (`embedding` stays text-only, images go to `main` then `sidecar`), with the hint highlighted in green. The `Vision` bullet only appears when it adds something: a bound vision role is always listed, while an unset one is hidden as soon as the main or sidecar model can already see images, and the `Decision` bullet is only listed while a decision model or endpoint is configured. `/providers` prints one line per role under the provider it uses — with a cyan `vision` tag on models that can see images — and an `Unassigned roles` block that repeats the same fallback wording for every role still unset.
- `/status` shows the same role wiring as the startup banner: the fixed `Model`/`Vision`/`Sidecar`/`Decision model` rows are replaced by one `Rol [provider] model` row per role, each carrying the cyan `vision` tag when its model can see images, and the provider endpoint row is gone because `/providers` owns endpoints. Role labels now match the names used by `/setmodel` (`Main` instead of `Model`, `Rabbit/Fast` for the fast model), and the vision row follows the same listing rule as the banner. The remaining configuration variables (UI, thinking, hidden thinking, tools, assisted, context usage, messages, yes/plan mode, offline, pinned contexts, mission) are unchanged.

- Model capability tags share one palette across the whole app. The colors now come from a single `tui.CapabilityTag` renderer (xterm-256), so the same tag looks identical in `/models`, `/setmodel` and the onboarding wizard: `completion` light gray, `tools` amber, `thinking` violet, `vision` cyan, `embedding` pink, `decision` orange; non-capability tags (such as `recommended`) stay gray. The startup wordmark is now lime green instead of cyan.

- Session compaction is token-based: `Session.CompactTo(keepTailTokens)` keeps the newest messages within a token budget (minimum four, sliding the cut back to keep assistant `tool_calls` paired with their results), preserves the first user message without duplicating it, and carries a prior `[Earlier conversation summary]` forward into the next summary input. The automatic trigger (`compactBestEffort`) fires when the *masked* transcript exceeds `COMPACT_AT_PERCENT` of the transcript budget or history exceeds 300 messages; `/compact` keeps its threshold gate and uses `ContextWindow/4` as the kept tail. Transcript rewrites bump a session generation counter so wire-window state resets safely.

- The system prompt is now assembled from embedded `text/template` files (`internal/prompt/templates/*.md`) and reordered for KV-cache friendliness: stable body (base + environment + pinned context + tool guidelines + skills), then plan/review/offline mode blocks, then the mission block, and the user goal last. Models with native tool calling no longer receive the XML `<invoke>` protocol catalogue; it is only rendered when XML mode is active (unknown/unsupported tools, or a model that already rejected tools at the wire level). The durable progress block and the mission continuation turn count moved out of the system prompt into a per-request trailing `[runtime_reminder]` that is never persisted in the transcript. File-write completion notes and the tool-result envelope footer were shortened.

- Workspace domain boundary protection: the directory where `vibe` was executed and its subdirectories define the active workspace domain. File tools (`Read`, `Glob`, `Grep`, `DescribeImage`, `Write`, `Edit`, `NotebookEdit`, `GitDiff`) and shell commands (`Bash`, `InteractiveBash`) targeting or referencing files and directories outside the workspace domain require explicit user consent via the permission prompt with an informative warning card. Shell commands are parsed to detect external paths, directory traversals (`..`), tildes (`~`), and `cd` targets, bypassing assisted auto-approval when targeting external paths. Permissions can be granted once, for the session (`Allow this session` remembering the path or non-system folder tree until exit), or persistently (`Always allow` / `Always deny`). Safe in-domain operations and user-supplied files (such as clipboard images from `/paste`) remain prompt-free.

- `/offline [on|off|status]` slash command and `--offline` CLI flag to toggle offline mode. When enabled, network tools (`WebSearch`, `WebFetch`, `HTTPRequest`) and external shell commands (`curl`, `wget`, `git clone`, `npm install`, etc.) are blocked, while local loopback requests (`localhost`, `127.0.0.1`, `::1`) remain allowed for local testing and services. Shell commands are semantically inspected by JEV Style (or regex heuristics) to prevent external outbound requests. Displays in `/status` and the startup banner, and injects an `# Offline Mode (enabled)` guidance block into the model's system prompt.
- `/goal <objective>` slash command (and `/mission start <goal>`) to initiate autonomous missions from the user's side. The agent starts with a phased execution protocol: Phase 1 organizes a concrete step-by-step plan with explicit verification criteria via `TodoWrite` and clarifies any ambiguities with the user (e.g. via `AskUserQuestion`), and Phase 2 executes the plan autonomously in unattended mode without stopping for routine approvals until the goal is fully accomplished (`MissionComplete`) or blocked (`MissionBlocked`).
- Session compaction summary now falls back to querying the primary model (`cfg.Model`) when no sidecar model is configured (`SidecarModel`), ensuring intelligent semantic summaries of long-running sessions even without a separate sidecar model.
- `/mission` slash command to end an agent-managed mission from the user's side, without waiting for the model to call `MissionComplete`. `/mission` shows the current mission (goal, status, continuation turns), `/mission done [summary]` marks it complete (for example when the user did the work manually), and `/mission cancel [reason]` stops it without completing it. Completing or cancelling also records a system note so the model learns the mission was closed by the user on its next turn. Missions remain agent-started: there is no command that begins one.
- File tools (`Read`, `Write`, `Edit`, `NotebookEdit`, `DescribeImage`) resolve relative paths against the session working directory by default, so the agent can edit session files without hardcoding absolute paths. A unique basename is resolved from path memory, ambiguous ones go through JEV Style/sidecar disambiguation, and a full path is only needed for files outside the session. The model-facing prompt and path-error hints now state this rule instead of requiring absolute paths.
- JEV Style v3 support with own endpoint and JSON structured I/O: `--jevstyle-v3-endpoint`, `VIBE_CODER_JEVSTYLE_V3_ENDPOINT`, `JEVSTYLE_V3_ENDPOINT` config, `/jevstyle v3` slash command with interactive mode selection and connection validation. v3 uses typed questions (`noul`, `choice`, `score`) with structured answers including probabilities and confidence. Danger assessment and goal completion use ordinal score scales for nuanced decisions. Low-confidence classifications are marked with `(uncertain)` suffix.
- `/paste` and `/image` slash commands to send clipboard content (text, image, or file) to the agent with an optional prompt. Auto-detects content type and injects images via the vision pipeline, text inline, or file paths for the agent to read. Images are attached as native model input, so the user's prompt alone is the question. Pasted images are stored in a per-session media directory so the transcript marker keeps resolving on later turns and after a resume. Cross-platform: macOS (pngpaste/pbpaste), Linux (wl-paste/xclip), Windows (PowerShell Get-Clipboard).

- Branded repository assets (`assets/logo.svg`, `assets/logo-mark.svg`) and a
  refreshed README header with badges and a table of contents.
- Continuous integration workflow (formatting, vet, tests, RAG-tagged tests, and
  a cross-compilation matrix), issue/PR templates, and Dependabot updates.
- `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, and this changelog.
- JEV Style decision model configuration support across CLI flags (`--jevstyle-model`, `--jevstyle`), environment variables (`VIBE_CODER_JEVSTYLE_MODEL`, `VIBEGO_JEVSTYLE_MODEL`), config file (`JEVSTYLE_MODEL`), `/jevstyle` slash command, and `--save` persistence.
- JEV Style assisted command execution mode (`--assisted-yes`, `/yes assisted`, `/jevstyle assisted on`) allowing automatic approval of safe commands while prompting for dangerous actions. Includes config file persistence (`ASSISTED_YES`), startup banner indicator (`(assisted enabled)` in green when active, `(run '/yes assisted' to enable)` in white when inactive), auto-deactivation and graceful fallback to manual approval if the model is absent or errors, and setup suggestion tips when configuring JEV Style models.
- Agent tool `JevDecide` exposed to the primary coding model and sidecars to query the JEV Style decision model for second opinions, safety validations, and discrete choices.
- Automatic session resume: starting `vibe` in a directory automatically loads the most recent session for that directory, displaying `(resumed)` next to the session ID in the startup banner. Added `-n`/`--new` CLI flag to bypass auto-resuming and start fresh.
- Session origin project path tracking: saved sessions persist the directory where they were initialized (`project_path` in `<id>.ctx.json` sidecar and `session-projects.json` fast index), and `/sessions` displays a formatted `PATH` column with home-relative (`~`) shorthand and directory hierarchy preservation.
- Decision workflows powered by JEV Style: workspace path disambiguation, autonomous mission goal completion verification, tool failure root-cause diagnosis hints, and conventional commit type classification.
- Temporal (ephemeral) session mode (`-t`, `--temporal`, `--temp`, `VIBE_CODER_TEMPORAL`): runs an ephemeral session where conversation history, transcripts, and session indexes are discarded on exit, while files and workspace changes made by the agent remain on disk. Includes red `(temporal)` banner status, `/new` reset support, and promotion to a permanent session with `/promote`.
- Isolated session mode (`--isolated`, `--isolate`, `VIBE_CODER_ISOLATED`, `ISOLATED`): runs a project-local session stored in a single `.vibe-isolated.jsonl` file strictly within the working directory, inaccessible to other folders and omitted from global session state. Automatically detects and loads the folder's isolated session on startup (with yellow `(isolated)` banner status), and resets/truncates the file on `/new`.
- First-run onboarding now also offers the optional JEV Style decision model, alongside the primary and sidecar models, and shows it in the closing summary. (Superseded by the provider registry above.)
- Numbered model pickers for `/model`, `/sidecar`, and `/jevstyle`: each lists the installed models once with capability tags and lets you choose by number (interactively or as an argument, e.g. `/model 2`), type a model name, press Enter to keep the current selection, or `[0]` to disable the sidecar/JEV Style role. (Superseded by `/models` + `/setmodel` above.)
- `/models` lists every installed model, numbered and tagged, marks which one each role currently uses, and explains how to switch with `/model <n>`, `/sidecar <n>`, or `/jevstyle <n>` and persist with `/save`. (Superseded by `/models [PROVIDER]` above.)
- `/redo` re-prints the last assistant response from the session (fully rendered, with the preceding user prompt for context), handy to recover where you left off after reopening `vibe`.
- `/promote` (alias `/keep`) keeps a temporal session by promoting it to a permanent, saved session.

### Changed

- Autonomous mission verification now feeds the JEV Style verdict back to the model: when JEV Style judges the mission goal as not yet complete, the runtime injects an explicit reminder telling the model not to call `MissionComplete` and to keep executing the checklist. Works with any configured JEV Style decision model (v1/v2 or v3) and does not require assisted permission mode.
- `/status` (aliases `/info` and `/stats`) now renders a colored, banner-style summary of the current configuration — session, model, sidecar, JEV Style, Ollama host, UI, vision/thinking/tools, whether thinking output is hidden, JEV Style assisted state (from the effective runtime mode, which can auto-disable), yes/plan mode, and context usage. Plain output stays line-based for logs and pipes.
- `/save` now persists model/thinking settings and no longer promotes a temporal session automatically; use `/promote` to keep a temporal session. Settings changed by `/setmodel`, `/provider`, `/sidecar`, `/decision`, `/think`, and `/hide-think` are still persisted with `/save`.
- First-run onboarding lists the installed models only once and reuses the same numbering for the primary, optional sidecar, and optional JEV Style prompts (previously the tool-capable list was printed again for each role). Entries are tagged `recommended`/`tools`/`vision`/`thinking`, and the primary selection rejects models that do not report tool support. (Superseded by the main-model-only first run described above.)
- Empty sessions with 0 messages are no longer persisted to disk, preventing clutter from aborted or empty CLI/REPL runs. `/sessions` and `ListSessions` automatically skip and clean up stale 0-message session files.
- Fixed Ollama `temperature` option serialization to prevent omitting `0` for deterministic decision models.

- Styled startup banner now shows a colored wordmark with aligned runtime facts;
  plain output is unchanged for scripts and pipes.

### Fixed

- `AskUserQuestion` prompts now take their default instead of blocking forever: a lone ESC (arrow keys and paste still work, they arrive as a burst) and the new `ASK_TIMEOUT_MS` / `VIBE_CODER_ASK_TIMEOUT_MS` deadline both answer option 1, and a timeout announces the choice it made (`No answer after 30s: using the default [1] ...`) because the user may have walked away. Option 1 is documented as the default and the tool now tells the model to list its recommended option first. Each option also accepts an optional `description`, rendered dimmed beside its label, so a question can explain the tradeoff of an answer without bloating the label.

- Fixed `AskUserQuestion` answering blind: the typed choice never appeared on screen and keystrokes could be swallowed. The tool opened its own `bufio.Reader` over `os.Stdin` while the TUI already owned that descriptor and the double-ESC monitor held the terminal in non-canonical mode with echo disabled, so nothing ever echoed the characters and the answer only became real on Enter. The tool now asks through the UI (`Asker`, wired in `cmd/vibe/main.go` when stdin and stdout are terminals), which pauses the ESC monitor, draws the same card, and reads the line with the UI's own echoing line editor; answer matching and the invalid-input retry stay in the tool, so the retry note is shown above the prompt instead of redrawing the card. Headless runs and tests keep the stdin path through `NewAskUserQuestionToolWithIO`.

- Fixed a turn ending in silence: no answer, no `responded in` footer and no error, which reads exactly like a crash. Three give-up paths returned success after the model produced nothing — repeated empty replies (`handleEmptyChatResponse`), replies with no visible text (reasoning only), and a reply carrying only an unknown tool envelope. They now report an `empty assistant response`, so the interactive REPL offers its existing retry prompt (`Model returned an empty response. Retry this step? [Y/n]`) and one-shot runs print the failure instead of exiting cleanly. Retries also stopped repeating the identical request that had just failed: the runtime injects a reminder naming what was missing, so the next attempt is a different prompt and the model is told to answer in plain text or call one tool. Declining the retry prints that the turn ended without an answer, and a mission pause no longer adds a duplicate error line.

- Fixed a checkpoint aborting the turn mid-task with `error: checkpoint requires one file inside the repository`. The pre-edit snapshot before `Write`/`Edit` was treated as a precondition: any target it refused — a file outside the repository, a path through a symlink, a protected or oversized file, an empty `file_path` — returned an error from the tool executor and ended the run, so a long session died the first time the agent touched something like `~/.config/...` or `/tmp/...`. A checkpoint is a best-effort safety net that only ever covers files inside the repository, so those failures are now logged and the edit proceeds, and a failure to record the post-image no longer discards the edit that already succeeded. An abandoned pre-image from an interrupted edit is also dropped instead of making every later checkpoint fail with `previous checkpoint is still pending`.

- Fixed deceptive path compaction in permission dialogs for `Write` and `Edit`: when a target path triggers an out-of-domain warning (`domain_warning`), the full uncompacted path is now displayed (`FILE: /root/exports/newdata.md` instead of `FILE: exports/newdata.md`), preventing confusion where an external or root path appeared to be a relative path inside the workspace.
- Rescued pseudo-root file targets generated by models in `ResolveTarget`: models frequently conflate the project root with the Linux filesystem `/root` (e.g. `/root/exports/newdata.md` when the session is in `/media/datamac/temp`), or emit leading slashes (`/nonexistent_dir/...`) thinking of the workspace root. `ResolveTarget` now detects these pseudo-root patterns and transparently anchors them to the session working directory.

- Fixed a broken MCP server silently taking down the ones behind it. `InitAndWrapAll` returned on the first failure while iterating a map, so an unstartable server dropped every server not yet reached — and which ones survived changed between runs — with no message anywhere; each server is now loaded on its own and its failure is reported in the `mcp` block. Fixed MCP clients becoming unusable after a restart: `Stop` closed the `done` channel and `Start` never armed a new one, so every later call failed with `mcp client stopped`.

- Fixed background commands skipping the mandatory confirmation check, and closed the gaps in the confirmation list itself. The always-confirm test ran only for `Bash` and `InteractiveBash`, so a catastrophic command sent through `BackgroundRun` — which carries the same `command` parameter — was never treated as always-confirm; every shell tool now shares one gravity classifier, and `BackgroundRun` goes through the same assisted-mode command review instead of the non-shell action path. The offline-mode network check had the same shape and now covers `BackgroundRun` too, so a background command cannot reach the network while `--offline` is set. The list was four regexes (`rm -rf /`, `sudo`, `mkfs`, `dd.*of=/dev/`) and missed `rm -rf ~`/`$HOME`/`*`/`.`/`..`, a recursive delete of a system root or of the workspace itself, `git push --force`, `git filter-branch`, `git reset --hard`, `git clean -fd`, `git checkout .`, recursive `chmod`/`chown` on a system root, `curl … | sh`, `shutdown`/`reboot`, `npm publish`, and every wrapper form (`nice`, `bash -c`, `env`, `xargs`), which is now resolved to the command it runs.
- Fixed an isolated folder losing its isolated mode after `/new`. Clearing an isolated session truncated `.vibe-isolated.jsonl` to zero bytes, and a folder counts as isolated only while that file has content, so the next `vibe` there silently started a user-level session and wrote it — with its metrics and the project index — into the state directory. A cleared isolated session now keeps a marker line, so the folder keeps detecting the mode while loading nothing. `/clear session` had the mirror problem: it looked the transcript up in the user-level sessions directory, so the folder file survived while the run reported discarding the session, and it now resets the folder file like `/new`.

- Fixed isolated runs leaking into the user-level directories. An isolated run keeps its transcript in the folder, but it still wrote the debug log (`~/.config/vibe-coder/vibe-coder.log`, which carries CLI arguments) and the prompt history (`<state-dir>/history.txt`), created the config, state, and sessions directories even when nothing was stored there, wrote `/save` settings and remembered tool permissions into a folder-local settings file instead of the shared config, and let `/clear sessions --yes` or `/sessions delete --all` delete every saved session. `config.Load` now settles the isolated mode before the first writable path opens — including a folder that already holds an isolated session, so the auto-detected case is contained too — `Config.EnterIsolatedLayout` moves only the prompt history into the folder, `Config.LogPath` reports no log at all for isolated and temporal runs (`logger.Init` now takes the file path and stays off for an empty one), isolated runs record neither metrics nor a mission run log, the shared directories are neither created nor written, and deleting sessions from an isolated run only clears the folder-local session. Settings (models, providers, `SIDECAR_DISABLED`, remembered permissions) keep going to the shared config file in every mode. A temporal run also keeps its RAG index in memory instead of writing `<state-dir>/rag.db`, and creates none of the user-level directories either, so it leaves no trace at all.

- Fixed the fast-model fallback chain disagreeing with what the UI promised. The README and the intro describe read-only retrieval as degrading from `rabbit` to the `sidecar` and then to the main model, but the runtime always handed sub-agents the main client and model, so the intro's fallback line named a model the runtime never used. `Config.FallbackRoleModel` now walks the displayed chain as data (`roleFallbackChain`: `rabbit` and `decision` degrade to the sidecar and then to main, `sidecar` straight to main) and reports which role it landed on, the sub-agent receives the resolved connection and model through `SetFastClient` instead of assuming the main one, and `rabbitClientFor` returns no client when the rabbit provider has no endpoint so the chain can take over. A bound rabbit still wins, including on a provider of its own.

- Fixed the `responded in Xs` footer growing for the whole session instead of measuring the current turn. In interactive (TTY) sessions the turn timer was only restarted on the non-interactive input path, so it kept counting from startup and every new user message simply added to the previous elapsed time. The UI now exposes `StartTurn()`, the agent restarts the timer at the top of each `Run`, and the input reader no longer resets it as a side effect of secondary prompts.

- Fixed long autonomous runs failing against strict OpenAI-compatible servers with `400 Bad Request` / `No user query found in messages.`. The rolling transcript window in `buildOllamaMessages` trims the history to a character budget, and that cut could drop the user turn entirely (or collapse the window to a single oversized tool result). The trimmed window is now repaired before it reaches the wire: orphaned tool results whose assistant `tool_calls` fell outside the cut become user observation envelopes, and a window with no user-role message is re-anchored on the most recent user request.

- Fixed `DescribeImage` failing with `model returned empty description` on reasoning models served by OpenAI-compatible endpoints (llama.cpp, vLLM, LM Studio). Those servers ignore Ollama's `think: false`, so reasoning consumed the 512-token budget and left `content` empty. Vision calls (main model and sidecar) now use a 2048-token budget, strip inline `<think>` blocks, and fall back to `reasoning_content` when `content` is empty.

- Fixed vision capability detection for OpenAI-compatible endpoints by parsing `architecture.input_modalities` (e.g. `["text", "image"]` from llama.cpp and vLLM), `modalities`, and model metadata from `GET /v1/models`. Previously, models on OpenAI-compatible servers whose names lacked hardcoded substring keywords were marked as known non-vision models, causing the agent to falsely instruct the model that it could not see and omit image payloads. Models without declared capability metadata now remain `unknown` rather than disabled, ensuring images are sent directly without disabling vision.
- Fixed Ollama endpoint normalization to default to port `11434` when the port is omitted (e.g. `http://mac-mini.local` or `mac-mini.local` resolving to `http://mac-mini.local:11434` instead of defaulting to port 80 and failing with `connection refused`).
- Added automatic main model vision fallback to `DescribeImageTool`: if the sidecar model fails (due to network unavailability, refused connections, or errors) and the primary model has vision capability, `DescribeImage` falls back to describing the image via the primary model instead of aborting the tool call with an error.
- Fixed multimodal image data URL encoding in OpenAI chat completion requests to detect the appropriate MIME type (JPEG, PNG, GIF, BMP, WebP) from payload magic bytes rather than forcing `data:image/png;base64,` on JPEG payloads.
- Fixed terminal session output buffer slicing in `internal/terminal/session.go` to prevent slice bounds out of range panics during concurrent stream reads.
- `/model` no longer reports wrong (or borrowed) capabilities for a specific tag. `applyModelSwitch` read only the capability snapshot cached at startup, and `LookupVision` fell back to the *base* name when an exact tag was missing, so selecting e.g. `…-GGUF:fixed` (which advertises `vision`/`thinking`) could report `vision: no, thinking: no` by adopting the sibling `…-GGUF:Q4_K_M`'s lesser capabilities. The switch now re-checks the selected model live via `/api/show` and caches the result, and a name that pins an explicit tag (other than `:latest`) is never resolved through a different tag: a missing tag stays `unknown` instead of a confident, wrong answer.
- Pasted images no longer send the model chasing a file path. After resolving an `[image path=...]` marker the runtime replaced it with `(image attached: <path>)` and the sidecar path did the same with `[sidecar-vision file=<path>]`, so a model that already had the image as pixels also received a filename. Combined with the vision prompt's "use Read on the image file to attach it", the model would call `Read`/`DescribeImage` on a path it did not need — resolving a bare clipboard basename against the session working directory gave `No such file or directory`, and the retry (`ls -l vibe_clipboard_<random>.png`) looked like an unknown path, so JEV Style dropped to low confidence and asked the user for permission to inspect the file they had just pasted. Images now arrive as native Ollama image payloads behind a pathless `(image attached)` note (or a pathless `[sidecar-vision]` block), the vision prompt states that images the user sends arrive as visual content and must not be Read or `DescribeImage`d, and `/paste` no longer appends a "look at this file" instruction. Failure notes still name the path, since those need debugging.
- JEV Style no longer treats a path the user supplied as an unknown one. The assisted-mode decision prompt received only the tool arguments, so a clipboard file such as `vibe_clipboard_<random>.png` (or any file the user pasted rather than the agent chose) read as an opaque name and the decision dropped to low confidence, prompting the user for their own file. `/paste` and `/image` now register the paths they extract on the permission manager, and assisted mode forwards them to the decision model as runtime context ("supplied by the user via /paste, not chosen by the agent"). Matching accepts the absolute path or the basename, and the note always reports the full path. Deciders without the context-aware `AskSafetyWithContext` keep working unchanged.
- `/paste` and `/image` no longer delete the pasted image before the agent reads it. The extracted image was written to the OS temp dir and then removed by a `defer` inside `PasteTaskFromSlash`, which ran before the message ever reached the model. Because the image marker is plain text (`[image path=...]`) resolved to real bytes only at send time, the model was left pointing at a file that no longer existed — it either saw `(image unavailable: stat image: ...)` or tried to inspect the path and got `No such file or directory`. Pasted images now land in a per-session media directory (`<sessions-dir>/media/<session-id>/`) that lives as long as the transcript referencing it, and is removed together with the session by `/sessions` delete, the empty-session sweep, and delete-all. `clipboard.Paste` takes the destination directory, and `Content.Cleanup` is gone: the image file is now owned by the session, not by a throwaway temp file.
- Vision and sidecar calls no longer return empty results on thinking-capable models. `DescribeImage` failed with `vision failed: model returned empty description`, and sidecar summaries/path disambiguation could fail the same way, because the `think` field was omitted and Ollama enables thinking by default on capable models: the reasoning tokens consumed the small response budget, leaving `content` empty. These calls now send `think:false` explicitly so the model produces the actual answer instead of reasoning. Covers the main-model vision fallback, the sidecar image description, and the sidecar text helpers.
- Streaming no longer drops whitespace-only deltas. Models that emit one character per chunk (some Gemma builds do) had every space and newline silently discarded, collapsing the assistant reply into a single run-on line with no list breaks.
- JEV Style assisted mode now reviews and auto-approves safe actions of every tool that would otherwise prompt — shell commands, network tools (`WebSearch`/`WebFetch`/`HTTPRequest`), file mutations (`Write`/`Edit`/`GitUndo`), and unknown/MCP tools. Mandatory shell confirmations (`sudo`, `rm -rf /`, …) and persistent denials are unchanged. The terminal always reports the outcome: `✓ <tool> approved by JEV Style assisted mode (<latency>)` when approved, `⚠ <tool> flagged as risky by JEV Style (<latency>) · asking for permission` when rejected, plus notices when the action cannot be classified or when JEV becomes unavailable and assisted mode disables itself.
- Slash command tests now write settings to a temporary directory instead of creating a `vibe-coder.env` artifact in the package; the stray tracked file was removed.
- Interactive input no longer desyncs the terminal cursor. Two root causes were
  fixed: (1) `insertRune` advanced the tracked screen column *before* redrawing,
  so every mid-line insert made `redraw` move one cell too far left, shifting
  the text and erasing the space after `user >`; (2) width was measured in runes,
  not terminal cells, so the double-width `👤` prompt icon (and any emoji/CJK
  typed by the user) threw the cursor off by one. Moving with the arrow keys no
  longer overlaps letters, typing lands at the cursor, and backspace can no
  longer erase the prompt. Wide runes are erased by both cells they occupy.
- Restored the macOS build of the TUI: terminal attributes use the Darwin/BSD
  `TIOCGETA`/`TIOCSETA` ioctls instead of the Linux-only `TCGETS`/`TCSETS`.
- Applied `gofmt` to files that had drifted from the canonical format.
- Removed superfluous blank lines and orphan prefix bars in thinking blocks and assistant turn completion footers (`thought for Xs` and `responded in Xs`).
