# LSP diagnostics for edits

Objective: give the agent authoritative, cheap language-level feedback on the file it just edited. Today the only post-edit signal is `AutoTest` (`internal/git/autotest.go`), which shells out to `go test ./...`, `pytest`, `vitest` or `cargo test` and costs a minute plus a turn to discover a typo. A language server reports the same class of error in hundreds of milliseconds for tens of tokens, which is the difference between a local model converging in 3 turns and in 12.

Branch: `main` (staged work-unit commits, no worktree — matches `odd/tasks/provider-registry.md`)
Delivery strategy: `ask-on-risk`
Test runner: `go test ./...`

## Specs

- **S1** A new `internal/lsp` package holds a minimal LSP client over stdio: JSON-RPC 2.0 framing with `Content-Length` headers, `initialize` + `initialized`, `textDocument/didOpen`, `textDocument/didChange` (full-text sync) and the `textDocument/publishDiagnostics` notification. Only this subset of LSP 3.17 is implemented, so gopls-style push diagnostics are enough and no pull request (`textDocument/diagnostic`) is needed.
- **S2** Servers are resolved per language from the same workspace markers the auto-test already probes (`internal/git/autotest.go:detect`): `go.mod` → `gopls`, `package.json` → `typescript-language-server`, `pyproject.toml`/`pytest.ini` → `ruff server`/`pylsp`, `Cargo.toml` → `rust-analyzer`. A server is usable only when its binary is on `PATH` (`exec.LookPath`); the first positive resolution is cached for the session, mirroring `AutoTest.detectCached`.
- **S3** One server process per language per session, started lazily on first need and reused across every edit and turn. `shutdown` + `exit` on agent exit, process killed on cancellation, so no orphan language server is ever left behind (the same cleanliness bar as isolated sessions).
- **S4** Diagnostics are push-based and therefore asynchronous. After `didChange`, the client waits for the notification carrying the version it just sent, bounded by a timeout (default 5000 ms). On timeout it returns what arrived, or nothing; it never hangs the turn.
- **S5** The model-facing payload is severity-first and bounded: `error`, then `warning`, then `info`/`hint`; one line per diagnostic as `<file>:<line>:<col> <severity> <message> [<source>]`; the whole result passes through the shared output cap (`tools.OutputLimitBytes`) and truncation is stated explicitly with the count left out, like the `Read` truncation note.
- **S6** A `Diagnostics` tool is exposed to the model, accepting `file_path` and an optional `severity` filter. It is read-only (`EffectRead` in `tools.EffectOf`), so it stays available under plan and review mode and never asks for permission. On a clean file it answers in one line instead of nothing, so the model knows the check actually ran.
- **S7** Automatic post-edit path: after a successful `Write`/`Edit`, diagnostics for the edited file are recorded as a `[DIAGNOSTICS]` observation next to the existing `[AUTO-TEST]` call in `internal/agent/tool_exec.go`, through the same `recordToolObservation` route. It runs only when the LSP is enabled.
- **S8** On a single edit, diagnostics run before the auto-test, and when they report at least one error the auto-test is skipped for that edit: a red squiggle that arrived in 200 ms tells the model more than a suite run that costs a minute, and the model can re-run tests itself once the file is clean.
- **S9** Configuration follows `defaults < config file < env < CLI`: `LSP_ENABLED` (auto — on when a server is available), `LSP_SERVERS` (override the language → command map), `LSP_AFTER_EDIT` (on), `LSP_TIMEOUT_MS` (5000), with `VIBE_CODER_LSP_*` env variants. `/status` reports the resolved state.
- **S10** A broken language server never degrades the session: a missing binary, a failed handshake, a crashing server or an unsupported language all resolve to "no diagnostics", silently as far as the model is concerned and only visible in the debug log.
- **S11** Diagnostics are injected as transcript observations only. They must not touch the system prompt, which was reordered for KV-cache friendliness.
- **S12** The prompt template tells the model that diagnostics are authoritative for the file it edited and that it should clear reported errors before running the test suite.
- **S13** The protocol layer is tested against a stub language server (a Go test binary speaking the handshake over stdio), so framing, severity ordering, timeouts, truncation, and the "no server available" path are covered without requiring gopls on the test machine.

## Log

- L1 (user, verbatim): "vamos con el LSP"
- D1 (decision): the LSP lands as one engine with two entry points — an on-demand `Diagnostics` tool and an automatic post-edit observation — because the automatic path is where the leverage is for a local model (it does not know it should check) while the tool is the smaller, safer first step and is reused by the automatic path.
- D2 (decision): diagnostics replace the auto-test on a red edit rather than running beside it. Running both would pay the expensive signal for information the cheap signal already delivered.
- D3 (decision): the `Content-Length` framing is implemented in `internal/lsp` instead of being reused from `internal/mcp`. That client exchanges newline-delimited JSON and drops every message without an id, which is exactly the shape of a `publishDiagnostics` notification, so neither its framing nor its read loop matched what push diagnostics need.
- D4 (decision): the client answers every server request, unsupported ones with method-not-found. gopls asks `workspace/configuration` during startup and publishes nothing until that request is settled, so an unanswered request is a silent hang rather than a missing feature.
- D5 (decision): S4's "returns what arrived, or nothing" is made explicit as a `bool` on the wait, and a clean file is a successful wait with an empty list rather than a timeout. A caller can then never present a list published for an older version as the answer to the edit it just made.
- D6 (decision): `textDocument/didClose` is added to the T1 surface beyond S1's list. A server reused across turns (S3) has to be able to release a document, and the call is part of the same protocol layer rather than of T2's lifecycle.
- D7 (decision, deviation from S13 as worded): the stub language server runs in-process over `net.Pipe`, not as a separate test binary on stdio. The client takes an `io.ReadWriteCloser`, so the process boundary is T2's business and framing, version-matched waits, timeouts and the "no publication" path are covered without a binary. The stub writes its own `Content-Length` headers by hand so a bug in `WriteMessage` cannot hide behind the stub built on it.
- D8 (observed): T1 landed as one work-unit commit of 1950 authored lines, over the 400-line review budget. It is a single unit — framing, the client core and the typed protocol layer have no consumer apart from each other — so the slice is the review candidate and the overage is reported rather than absorbed by splitting a package that does not compile usefully in halves.
- D9 (decision): detection reuses the auto-test's markers and its caching doctrine exactly: a positive answer is kept for the session because a server that exists does not stop existing, while a negative one is re-checked so installing the binary mid-session takes effect. A marker without a binary on `PATH`, and a binary without a marker, both resolve to nothing.
- D10 (decision): the server process is started with `exec.Command`, deliberately not `exec.CommandContext`. It is shared by every later edit, so a single call's context expiring must not kill the server other calls are still using; only `Manager.Close` owns the process lifetime. This is where S3's "killed on cancellation" is satisfied — on `Close`, not on every cancelled call.
- D11 (decision): stdin/stdout are plain `os.Pipe` ends assigned to `cmd.Stdin`/`cmd.Stdout`, not `cmd.StdinPipe()`/`cmd.StdoutPipe()`. `Wait` closes the pipes those helpers return, which races with a reader still draining them, and this client reads the server's stdout for the whole life of the session.
- D12 (decision, found by test): a handshake that never completes is killed outright instead of shut down politely. A graceful close against a server that has never answered spends the shutdown timeout plus the exit grace, which measured 7.3 s on a silent server — seconds taken straight out of a turn. `abort` exists for exactly this path; `close` stays the polite path for a server that did talk.
- D13 (decision, found by test): a cancelled call is answered with `context.Canceled` before anything else happens. Waiting on an already-started session and on a done context in one `select` picks between two ready cases at random, so the same cancelled call could return an error or a session; the explicit check makes it deterministic and also stops a cancelled call from spawning a server nothing is waiting for.
- D14 (decision): `internal/lsp` does not import `internal/logger`. A broken server is reported as an error carrying a bounded tail of its stderr, and the layer that wires it in (T4) decides what to log, so the package stays testable with no global logger while S10's "visible in the debug log" still holds.
- D15 (decision, deviation from S13 as worded): T2's stub server is not a separate test binary either. The fake server is a shell script named after the real binary, on a `PATH` the test controls, which re-executes the test binary into stub mode — so marker detection and binary lookup are exercised for real over a real process boundary, and no language server installed on the machine can change a result. The script `exec`s, so killing the server kills the stub and no shell survives holding the pipes.
- D16 (observed): T2 landed as one work-unit commit of 1827 authored lines, over the review budget for the same reason as D8 — registry, detection, lifecycle and engine have no consumer apart from each other — and a behaviour the tests found on the way in is worth more than the split would have been.
- D17 (decision): the `Diagnostics` tool is not registered by `RegisterDefaults`. It needs a source, and a default registration would hand every model a tool whose only possible answer in a workspace without a server is "no language server available". The CLI registers it only when a server actually resolved, so the tool list stays honest about what this workspace can do.
- D18 (decision): a missing or unsupported server is not an error result. The model cannot act on it, it needs no failure in its transcript, and it must not learn to avoid the tool; it gets one line and a hint to run the tests instead.
- D19 (decision): a wait that timed out is never rendered as a clean file. "No diagnostics" and "the server did not answer for the version just sent" are different answers, and only the first is evidence that an edit is clean; the stale case says so, both when the list came back empty and when it did not.
- D20 (decision): severity is a threshold, so `warning` means warnings and worse, and an omitted or out-of-range severity counts as an error instead of being filtered away — a server that says nothing about severity is still reporting something.
- D21 (decision, departure from the `Read` validator): relative paths are accepted and echoed back as given. `validateExistingFileForRead` in `internal/tools/path_diagnostic.go` rejects anything non-absolute while the assistant path hints tell the model to pass relative paths; the manager's `abs` already anchors a relative path to the working directory, and the echoed string is the one the model will reuse in its next edit.
- D22 (decision): the rendering is deterministic and byte-budgeted — sorted severity-first, then line, then column; positions printed one-based because that is what editors print; multi-line messages collapsed to one line; and a budget that drops whole diagnostics and states the count instead of cutting a line in half, with one oversized diagnostic still shown clipped rather than silently dropped.
- D23 (observed): T3 landed as one work-unit commit of 652 authored lines, over the review budget for the same reason as D8 and D16 — the tool, its tests and its registration have no consumer apart from each other.
- D24 (decision): the renderer is shared with the tool instead of written twice. `RenderDiagnostics` is exported from `internal/tools` and is the only place that turns a report into model-facing text, so the tool the model calls by hand and the observation it gets after an edit cannot drift apart; `HasErrors` applies the same severity rule the renderer documents, so "this edit is red" and "this edit shows an error" are one definition rather than two that agree by luck.
- D25 (decision, the point of S8): only a FRESH report can skip the suite. A list left over from an earlier version still renders, with its caveat, but never decides that the tests do not run. Skipping a suite on stale evidence is how a broken server silences a regression, and the cost of the mistake is asymmetric: one wasted minute against a test suite that never ran.
- D26 (decision): the observation says why the suite was skipped. An AUTO-TEST that simply does not appear reads like a bug and invites the model to run the suite anyway, which is the cost S8 exists to avoid, so the report ends with the reason.
- D27 (decision): every failure of the automatic path is silent to the model — no source configured, an unsupported file, a failed handshake, a crashed server, a timeout — and the auto-test does its job as if the feature were not there. The error goes to the debug log (D14), which is where a human looks; the transcript only ever carries what the model can act on.
- D28 (decision): support is checked before anything is spawned, so an edit to a file no server owns does not start one, and the UI shows a working indicator around the check because a cold language server indexing can take seconds that would otherwise read as a hang.
- D29 (decision): the `LSP_ENABLED` / `LSP_AFTER_EDIT` gate is not in this slice. The config task owns it and the wiring site in `cmd/vibe` is its natural home; until then the automatic path follows the presence of a resolved server, exactly like the tool.
- D30 (observed): T4 landed as one work-unit commit of 390 authored lines, inside the review budget — the only slice of this feature that is, because the engine, the process handling and the renderer it builds on were already reviewed and committed.
- D31 (decision): `LSP_ENABLED` defaults to `auto`, which is the old behaviour wherever nothing resolves, so the switch adds a way out instead of a new thing to configure. Every setting is reachable from all four layers, and the CLI uses the force form (`--lsp`, `--no-lsp`, `--no-lsp-after-edit`) rather than accepting a string value the file and env layers already spell out.
- D32 (decision): the manager is created even when the feature is off, and `/status` reports the state in three words — off, none for this workspace, or the family and command that will be spawned. A row that is absent when the feature is off cannot answer the question a user actually has.
- D33 (decision): an unrecognized `LSP_ENABLED` value lands on `auto`, not `off`. The safe reading of a typo is the one that only reports when a server answers; silently disabling the feature on a misspelling is the failure nobody debugs.
- D34 (decision): `LSP_SERVERS` splits each entry on its first colon, so a command containing a colon (a Windows path) survives, and a malformed entry is dropped rather than fatal. The override also needs no workspace marker, because naming a command is reason enough, and what actually resolved is what `/status` shows rather than what was typed.
- D35 (decision): the timeout is clamped to 250..60000 ms once every source has had its say, unlike the harness tunables which normalize before the CLI is applied because they are not settable from it. A zero or negative value takes the default 5000 ms. An explicit `on` with nothing resolved is logged at startup, since the alternative is a session that silently never checks anything.
- D36 (observed): T5 landed as one work-unit commit of 616 authored lines, over the review budget. The config layer, the wiring and the status row are one unit: a setting nobody can see in `/status` and a status row that reports what the wiring did not read are both half-features.
- D37 (observed): `internal/terminal TestSessionEchoAndExit` failed inside a whole-suite run and passes every time on its own; that package imports none of the packages this task touches, so it is a flaky PTY test under load, not a regression. It is recorded here so the next full-suite run does not re-open the question.
